## What Sentinel is
Continuous synthetic monitoring engine for Prometheus. Probes configured targets on a schedule
(decoupled from scrapes) and exposes state via `/metrics`. Product/design context lives in the docs —
do **not** re-derive:
- Design decisions + running status log: `brainstorms/2026-08-01-sentinel-design.md` (authoritative).
- Specs (reconciled to what's implemented): `README.md`, `architecture.md`, `configuration.md`, `metrics.md`, `Roadmap.md`.

`cmd/sentinel/main.go` and a collector registration in `serve()`.

## Adding the next protocol (the established recipe)
Mirror `internal/probe/dns` (simplest reference) or `internal/probe/http`:
1. `internal/config`: add the protocol block struct + field on `Target`; extend `validateTarget`'s
   protocol count and add a `validate<X>`; add any defaults in `applyDefaults`.
2. `internal/probe/<x>`: `Options`, `Prober` (implements `probe.Prober`, never returns error — failure
   is `Result{Success:false, FailureReason}`), `Diagnostics` (implements `probe.Diagnostics.ProbeType`),
   `Collector` (self-registering, reads `store.Snapshot()`, filters `rec.Type == ProbeType`, uses
   `metrics.BaseLabelValues`). Add a new `probe.FailureReason` only if needed (enum is extensible;
   update `failure_test.go` count + `metrics.md`).
3. `cmd/sentinel/main.go`: add a `buildProber` case and a `reg.MustRegister(<x>.NewCollector(st))`.
4. Tests: hermetic harness (httptest / local `dns.Server` pattern), `-race`.
5. Then an adversarial review subagent (see below), fix findings with tests, update docs, commit
   code + docs separately, and (on request) push/merge.
