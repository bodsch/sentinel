# Grafana dashboard

`sentinel.json` — probe state and failure reasons, latency histograms, HTTP
phase timings, DNS/TCP/TLS probes, certificates and chain, scrape cost, Go
runtime and process. Built from the metrics listed in
[metrics.md](../../metrics.md).

It is generated by `generate.py`. Change the script and run
`make dashboards`; an edit to the JSON is lost on the next run.

Import it under *Dashboards → New → Import*. It asks for a Prometheus data
source and offers the variables `instance` (from `sentinel_build_info`) plus
`environment`, `service`, `type` and `target` (from `sentinel_probe_success`).

`process_*`, `go_*`, `up` and `scrape_*` are joined on
`sentinel_build_info` by `(job, instance)`, so they only show Sentinel. That
requires every scrape target to have its own `(job, instance)` pair; check with

```promql
count by (job, instance) (process_cpu_seconds_total)
```

Counters and info series can have no series at all (`sentinel_probe_failure_info`
exists only while a target fails), so every single-value panel on them ends in
`or vector(0)` — without it a healthy setup shows »No data« instead of 0.
